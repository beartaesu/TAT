# 01 TAT MASTER — 통합 설계 기준

최종 갱신: 2026-08-05

## 문서 역할과 갱신 기준

- 역할: 프로젝트의 장기 통합 설계 기준
- 포함: 시스템 구조, SharePoint 데이터 모델, 화면·Flow의 큰 흐름, 확정 운영 원칙
- 제외: 일회성 오류 로그, 미검증 수식 원문, 당일 작업대장
- 갱신: 구조·목록·열·화면·Flow·운영 원칙이 장기 기준으로 확정 또는 폐기될 때
- 상세 오류와 실제 수식은 각각 02와 04에 기록하고, 결정 근거는 03에 기록한다.

## 1. 프로젝트 목적

Teams Power Apps에서 시험 접수를 입력하고 SharePoint Lists에 원본 데이터를 저장한다. 접수 이후 분석 진행, 결과 파일, 결과 발송, 세금계산서 및 정산 상태를 관리하며 Excel 2021은 Power Query·피벗·차트 기반 조회·보고 도구로 사용한다.

## 2. 운영 원칙

- 신규 데이터의 원본은 SharePoint이며 Excel은 조회·보고용이다.
- 회사 PC에서 사용자가 Power Apps, SharePoint, Power Automate를 직접 편집한다.
- 온프레미스 게이트웨이와 PC 설치 프로그램은 사용하지 않는다.
- 결과 폴더·Excel 생성과 미접수↔측정인 구분변경 후 폴더·파일명 변경은 `TAT_결과파일생성_App` 자동화로 처리하는 방향으로 변경했다.
- Power Apps 수식은 실제 컨트롤명·열명·Choice 값·Lookup 구조를 확인한 뒤 작성한다.
- 변경 수식은 삽입 조각이 아니라 `화면 > 트리 > 컨트롤 > 속성`과 붙여넣기용 전체 교체 수식으로 제공한다.
- 작업 지시는 연관된 3~5개 설정 단위로 묶는다.
- 작업 결과는 성격에 맞는 01~04 문서에 누적하며 모든 문서를 기계적으로 함께 수정하지 않는다.
- Git 반영은 `AGENTS.md`의 세션 단위 체크포인트 규칙을 따른다. 기능 검증 완료, 중요 오류의 결론 확정, 세션 종료 전, 사용자 즉시 요청 시 관련 변경을 묶어 `main`에 반영한다.

## 3. 핵심 업무 흐름

1. 접수 기본정보 입력
2. 분석항목 선택
3. 시료별 분석항목 배정
4. 검토 및 저장
5. 접수번호 발급
6. 접수헤더·항목상세·시료항목매핑 저장
7. 결과 폴더·결과 입력 Excel 생성 및 SharePoint 접수헤더 연결
8. 접수현황 조회 및 상세 진입
9. 접수상태·항목상태·의뢰구분 변경
10. 결과 발송 및 정산 관리

## 4. 의뢰구분과 접수번호

- 사용 구분: `미접수`, `측정인`, `과제`
- `일반` 구분은 사용하지 않는다.
- 미접수와 측정인은 상호 변경할 수 있다.
- 과제 접수는 의뢰구분 변경 대상이 아니다.
- 구분변경 시 새 접수번호를 발급하고 이전·최초 접수번호와 변경 이력을 보존한다.
- 2026-08-05 신규 테스트 `ES-DR-2026-025 → ENE-260805-016`에서 실제 폴더 이동과 폴더·Excel 파일명 변경은 성공했다.
- 신규 결과 Excel 생성 직후 구분변경을 실행하면 Excel Online 커넥터의 일시 잠금 때문에 `기존폴더이동및이름변경`이 실패할 수 있다. 충분히 기다린 뒤 Flow 실행 기록을 다시 제출하면 실제 파일 처리는 성공했다.
- 다만 실행 기록의 `다시 제출`은 Power Apps 호출 문맥이 없으므로 Flow 응답을 받아 수행하는 접수헤더 경로 4개 Patch가 실행되지 않는다. 향후 변경 Flow 내부에서 접수헤더·변경이력을 직접 최종 갱신하고 잠금 오류를 조건부 재시도하는 구조로 보완한다.
- 예시: `ENE-260804-011` → `ES-DR-2026-019`
- 과제는 과제별 접수 시작번호를 별도로 관리하며 기간 검증은 적용하지 않는다.

## 5. 주요 SharePoint 목록

### 접수헤더

주요 열:

- 제목: 접수번호 표시 열
- 의뢰구분, 의뢰일자, 접수상태
- 시료명 요약, 시료수
- 업체·현장 Lookup, 계산서 업체 Lookup
- 과제연결 Lookup, 과제명복사, 과제문서번호복사
- 결과폴더명, 결과폴더경로
- 결과엑셀파일명, 결과엑셀파일경로
- 결과발송여부, 정산상태, 세금계산서배정상태
- 예상종료일, 최종종료일, 완료여부, 비고
- 이전접수번호, 최초접수번호, 최초의뢰구분
- 구분변경여부, 최종구분변경일
- 폴더처리상태, 폴더처리오류

`폴더처리상태`에 수식에서 사용하는 값:

- `처리중`, `처리완료`, `처리실패`

과거 수동 처리 설계의 `수동처리대기`는 자동화 전환 전 기록이다. 실제 Choice 목록과 위 값의 생성 여부는 SharePoint에서 최종 확인한다.

### 접수항목상세

- 접수헤더 Lookup
- 접수번호 표시값
- 분석항목, 수량, 단가
- 분석상태, 분석완료일
- 삭제 및 일괄 상태변경 대상

### 접수시료항목매핑

- 접수헤더연결 Lookup
- 제목: `접수번호-시료순번-분석항목` 형식의 표시용 문자열
- 구분변경 시 Lookup은 그대로 유지하고 제목 속 접수번호만 신규 번호로 변경한다.

### 접수구분변경이력

- 제목: `변경전접수번호 → 변경후접수번호`
- 접수헤더연결 Lookup
- 변경전/후 구분 및 접수번호
- 변경일시, 변경자, 변경사유
- 처리결과: Flow 호출 전 `처리중`, 성공 시 `처리완료`, 실패 시 `처리실패`

### 기타 목록

- 현장마스터
- 계산서업체마스터
- 거래처담당자
- 분석항목마스터
- 세금계산서발행대장
- 과제 목록
- 접수번호관리

## 7. 결과 Excel 레이아웃

- B3: 업체명
- B4: 의뢰번호
- 분석항목은 10개 단위로 아래쪽 블록에 배치
- 각 블록에서 A6:A8 영역의 시험결과·Sample·정량한계 구조 유지
- 블록 사이 여백 1행
- 병합·테두리는 동적으로 처리하는 방향

## 8. 최종 저장 목표 순서

1. 접수번호 발급
2. 접수헤더 저장
3. 접수항목상세 저장
4. 시료명목록 생성
5. 분석항목목록 생성
6. `TAT_결과파일생성_App.Run(...)`
7. 반환된 폴더명·폴더경로·Excel 파일명·Excel 경로를 접수헤더에 Patch
8. 폴더처리상태·오류정보 갱신
9. 성공·실패 알림

2026-08-05 Power Apps에서 Flow 연결을 새로고침한 결과 `.Run(...)`이 요구하는 15개 입력의 이름·형식·순서를 확정했다. `btn최종저장.OnSelect`의 Flow 호출부 4곳을 모두 15개 인수 구조로 교체했으며, 인수 오류와 문법 오류가 해소됐다. 새 테스트 접수에서 결과 폴더·Excel 생성과 SharePoint 접수헤더 연결까지 정상 완료된 것을 확인했다.

## 9. 향후 안정화 작업

1. 변경 Flow의 잠금 오류 처리: Excel 잠금일 때만 일정 간격으로 제한 횟수 재시도하고, 최종 실패 시 오류를 기록한다.
2. 변경 Flow 내부에서 `접수헤더`의 결과폴더명·결과폴더경로·결과엑셀파일명·결과엑셀파일경로·폴더처리상태·폴더처리오류를 직접 갱신한다.
3. 변경 Flow 내부에서 `접수구분변경이력.처리결과`를 `처리완료` 또는 `처리실패`로 직접 갱신한다.
4. Power Apps 응답값의 결과폴더명·결과엑셀파일명에 변경 전 접수번호가 덧붙지 않도록 반환 수식을 교정한다.
5. Flow 실행 기록을 다시 제출해도 Power Apps 응답 소비 여부와 무관하게 SharePoint 상태가 최종 일치하도록 만든다.
