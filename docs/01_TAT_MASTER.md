# 01 TAT MASTER — 통합 설계 기준

최종 갱신: 2026-08-05

## 1. 프로젝트 목적

Teams Power Apps에서 시험 접수를 입력하고 SharePoint Lists에 원본 데이터를 저장한다. 접수 이후 분석 진행, 결과 파일, 결과 발송, 세금계산서 및 정산 상태를 관리하며 Excel 2021은 Power Query·피벗·차트 기반 조회·보고 도구로 사용한다.

## 2. 운영 원칙

- 신규 데이터의 원본은 SharePoint이며 Excel은 조회·보고용이다.
- 회사 PC에서 사용자가 Power Apps, SharePoint, Power Automate를 직접 편집한다.
- 온프레미스 게이트웨이와 PC 설치 프로그램은 사용하지 않는다.
- 결과 폴더·Excel 생성과 미접수↔측정인 구분변경 후 폴더·파일명 변경은 `TAT_결과파일생성_App` 자동화로 처리하는 방향으로 변경했다.
- Power Apps 수식은 실제 컨트롤명·열명·Choice 값·Lookup 구조를 확인한 뒤 작성한다.
- 변경 수식은 삽입 조각이 아니라 `화면 > 트리 > 컨트롤 > 속성`과 붙여넣기용 전체 교체 수식으로 제공한다.
- 작업 지시는 연관된 3~5개 설정 단위로 묶는다.
- 매 작업 완료 시 01~04 문서를 누적 최신화한다.

## 3. 핵심 업무 흐름

1. 접수 기본정보 입력
2. 분석항목 선택
3. 시료별 분석항목 배정
4. 검토 및 저장
5. 접수번호 발급
6. 접수헤더·항목상세·시료항목매핑 저장
7. 결과 폴더·결과 입력 Excel 생성 또는 수동처리대기 기록
8. 접수현황 조회 및 상세 진입
9. 접수상태·항목상태·의뢰구분 변경
10. 결과 발송 및 정산 관리

## 4. 의뢰구분과 접수번호

- 사용 구분: `미접수`, `측정인`, `과제`
- `일반` 구분은 사용하지 않는다.
- 미접수와 측정인은 상호 변경할 수 있다.
- 과제 접수는 의뢰구분 변경 대상이 아니다.
- 구분변경 시 새 접수번호를 발급하고 이전·최초 접수번호와 변경 이력을 보존한다.
- 예시: `ENE-260804-011` → `ES-DR-2026-019`
- 과제는 과제별 접수 시작번호를 별도로 관리하며 기간 검증은 적용하지 않는다.

## 5. 주요 SharePoint 목록

### 접수헤더

주요 열:

- 제목: 접수번호 표시 열
- 의뢰구분, 의뢰일자, 접수상태
- 시료명 요약, 시료수
- 업체·현장 Lookup, 계산서 업체 Lookup
- 과제연결 Lookup, 과제명복사, 과제문서번호복사
- 결과폴더명, 결과폴더경로
- 결과엑셀파일명, 결과엑셀파일경로
- 결과발송여부, 정산상태, 세금계산서배정상태
- 예상종료일, 최종종료일, 완료여부, 비고
- 이전접수번호, 최초접수번호, 최초의뢰구분
- 구분변경여부, 최종구분변경일
- 폴더처리상태, 폴더처리오류

`폴더처리상태`에 수식에서 사용하는 값:

- `처리중`, `처리완료`, `처리실패`

과거 수동 처리 설계의 `수동처리대기`는 자동화 전환 전 기록이다. 실제 Choice 목록과 위 값의 생성 여부는 SharePoint에서 최종 확인한다.

### 접수항목상세

- 접수헤더 Lookup
- 접수번호 표시값
- 분석항목, 수량, 단가
- 분석상태, 분석완료일
- 삭제 및 일괄 상태변경 대상

### 접수시료항목매핑

- 접수헤더연결 Lookup
- 제목: `접수번호-시료순번-분석항목` 형식의 표시용 문자열
- 구분변경 시 Lookup은 그대로 유지하고 제목 속 접수번호만 신규 번호로 변경한다.

### 접수구분변경이력

- 제목: `변경전접수번호 → 변경후접수번호`
- 접수헤더연결 Lookup
- 변경전/후 구분 및 접수번호
- 변경일시, 변경자, 변경사유
- 처리결과: Flow 호출 전 `처리중`, 성공 시 `처리완료`, 실패 시 `처리실패`

### 기타 목록

- 현장마스터
- 계산서업체마스터
- 거래처담당자
- 분석항목마스터
- 세금계산서발행대장
- 과제 목록
- 접수번호관리

## 7. 결과 Excel 레이아웃

- B3: 업체명

## 9. TAT_결과파일생성_App Power Apps (V2) 입력 — 2026-08-05 확정

| 순서 | 입력명 | 형식 |
|---:|---|---|
| 1 | 접수헤더ID | 숫자 |
| 2 | 접수번호 | 텍스트 |
| 3 | 의뢰구분 | 텍스트 |
| 4 | 현장명 | 텍스트 |
| 5 | 과제명 | 텍스트 |
| 6 | 시료수 | 숫자 |
| 7 | 시료명목록 | 텍스트 |
| 8 | 분석항목목록 | 텍스트 |
| 9 | 시료항목매핑 | 텍스트 |
| 10 | 처리모드 | 텍스트 |
| 11 | 변경전의뢰구분 | 텍스트 |
| 12 | 변경전접수번호 | 텍스트 |
| 13 | 변경전결과폴더경로 | 텍스트 |
| 14 | 변경전결과엑셀경로 | 텍스트 |
| 15 | 변경이력ID | 숫자 |

신규·수정 저장은 1~9번에 현재 접수 값을 전달하고, 10번은 각각 `신규` 또는 `수정`, 11~14번은 빈 문자열, 15번은 `0`을 전달한다. 전체 수식 기준본은 `formulas/scr검토저장_btn최종저장_OnSelect.powerfx`이다.

## 10. 15개 인수 적용 검증 — 2026-08-05

- `scr검토저장 > btn최종저장 > OnSelect`에 15개 인수 전체 교체본을 적용했다.
- Power Apps의 `15개의 인수가 필요한데 10개를 받았습니다` 오류와 빨간 문법 오류가 사라진 것을 사용자 확인으로 검증했다.
- 다음 검증은 새 테스트 접수 1건으로 최종저장을 실행하고 Flow 실행·폴더·Excel·반환 경로 Patch를 확인하는 것이다.
