# 01 TAT MASTER — 통합 설계 기준

최종 갱신: 2026-09-03

## 문서 역할과 갱신 기준

- 역할: 프로젝트의 장기 통합 설계 기준
- 포함: 시스템 구조, SharePoint 데이터 모델, 화면·Flow의 큰 흐름, 확정 운영 원칙
- 제외: 일회성 오류 로그, 미검증 수식 원문, 당일 작업대장
- 갱신: 구조·목록·열·화면·Flow·운영 원칙이 장기 기준으로 확정 또는 폐기될 때
- 상세 오류와 실제 수식은 각각 02와 04에 기록하고, 결정 근거는 03에 기록한다.

## 1. 프로젝트 목적

Teams Power Apps에서 시험 접수를 입력하고 SharePoint Lists에 원본 데이터를 저장한다. 접수 이후 분석 진행, 결과 파일, 결과 발송, 세금계산서 및 정산 상태를 관리하며 Excel 2021은 Power Query·피벗·차트 기반 조회·보고 도구로 사용한다.

## 2. 운영 원칙

- 신규 데이터의 원본은 SharePoint이며 Excel은 조회·보고용이다.
- 회사 PC에서 사용자가 Power Apps, SharePoint, Power Automate를 직접 편집한다.
- 온프레미스 게이트웨이와 PC 설치 프로그램은 사용하지 않는다.
- 결과 폴더·Excel 생성과 미접수↔측정인 구분변경 후 폴더·파일명 변경은 `TAT_결과파일생성_App` 자동화로 처리하는 방향으로 변경했다.
- Power Apps 수식은 실제 컨트롤명·열명·Choice 값·Lookup 구조를 확인한 뒤 작성한다.
- 변경 수식은 삽입 조각이 아니라 `화면 > 트리 > 컨트롤 > 속성`과 붙여넣기용 전체 교체 수식으로 제공한다.
- 작업 지시는 연관된 3~5개 설정 단위로 묶는다.
- 작업 결과는 성격에 맞는 01~04 문서에 누적하며 모든 문서를 기계적으로 함께 수정하지 않는다.
- Git 반영은 `AGENTS.md`의 세션 단위 체크포인트 규칙을 따른다. 기능 검증 완료, 중요 오류의 결론 확정, 세션 종료 전, 사용자 즉시 요청 시 관련 변경을 묶어 `main`에 반영한다.

### 기존 Excel 형식 내보내기 — 후속 기능

- Teams Power Apps에서 생성되어 SharePoint에 저장된 데이터를 기존 제공 Excel과 같은 행·열 구조로 다시 만들 수 있어야 한다.
- 기본 출력 열 순서는 `의뢰일자`, `접수번호`, `업체`, `계산서 업체`, `시료명`, `시료수`, `구분`, `분석항목`, `수량`, `단가`, `공급가액`, `부가세`, `항목별 총액`, `총금액`, `연도`, `월`, `주차`, `주차표시`, `TAT`, `표준처리기한`이다.
- 출력 한 행은 `접수항목상세` 한 행을 기준으로 하고, `접수헤더`, `접수항목상세`, 필요 시 `접수시료항목매핑`과 마스터 정보를 조합해 평탄화한다.
- 기존 형식과 같이 접수번호별 `총금액`을 첫 출력 행에만 표시할지, 부가세·항목별 총액·TAT·표준처리기한을 어떤 원본 열에서 산출할지는 구현 전 실제 SharePoint 열과 기존 Excel 결과를 대조해 확정한다.
- 구현 후보는 Power Automate의 Excel 표 생성 또는 Excel Power Query이며, 회사 PC 운영·갱신 방식과 대량 행 성능을 비교한 뒤 선택한다.

### 월별 입고량·성적서 발행 리드타임 지표 — 후속 기능

- 월별 총 입고 시료 수는 `접수헤더.의뢰일자`의 연·월로 묶어 `접수헤더.시료수`를 합산한다. 접수 건수와 시료 수 합계를 혼동하지 않는다.
- 접수별 분석완료일 기준값은 해당 접수의 `접수항목상세.분석완료일` 중 가장 늦은 날짜를 사용하는 방향으로 설계한다. 일부 상세가 미완료면 지표 포함 여부를 구현 전에 확정한다.
- 성적서 발행 리드타임은 접수별 성적서발행일에서 위 최종 분석완료일을 뺀 일수로 계산한다.
- 표시 지표는 2일 이내 준수 건수·준수율, 리드타임 50백분위수(P50), 95백분위수(P95)이다.
- 성적서발행일에 대응하는 실제 SharePoint 열이 없으면 `접수헤더`에 날짜 열을 추가해야 한다. 기존 `결과발송여부`만으로 발행일을 추정하지 않는다.
- 날짜가 비어 있는 건은 계산 대상에서 제외하고 별도 미입력 건수로 표시하며, 음수 리드타임은 데이터 오류로 분리한다.
- 2일 기준을 달력일로 계산할지 영업일로 계산할지와 화면 표시 위치는 구현 시작 전에 확정한다.

## 4. 의뢰구분과 접수번호

- 사용 구분: `미접수`, `측정인`, `과제`
- `일반` 구분은 사용하지 않는다.
- 미접수와 측정인은 상호 변경할 수 있다.
- 과제 접수는 의뢰구분 변경 대상이 아니다.
- 구분변경 시 새 접수번호를 발급하고 이전·최초 접수번호와 변경 이력을 보존한다.
- 2026-08-05 신규 테스트 `ES-DR-2026-025 → ENE-260805-016`에서 실제 폴더 이동과 폴더·Excel 파일명 변경은 성공했다.
- 신규 결과 Excel 생성 직후 구분변경을 실행하면 Excel Online 커넥터의 일시 잠금 때문에 `기존폴더이동및이름변경`이 실패할 수 있다. 이 작업에는 고정 간격 재시도 정책(2분 간격, 최대 3회)을 적용한다.
- 변경 Flow는 Power Apps 응답 소비 여부와 관계없이 접수헤더 경로 4개·처리상태와 변경이력 처리결과를 Flow 내부에서 직접 최종 갱신한다. 2026-08-13 실패 실행 재제출로 폴더·Excel·B4·접수헤더·변경이력의 최종 일치를 검증했다.
- 예시: `ENE-260804-011` → `ES-DR-2026-019`
- 과제는 과제별 접수 시작번호를 별도로 관리하며 기간 검증은 적용하지 않는다.

### 현장마스터 자동 관리 — 2026-09-03 단순화

- 별도 `업체마스터`는 만들지 않는다. 기존 `현장마스터`를 업체 기본 행과 사용자 추가 현장을 함께 보관하는 목록으로 사용한다.
- `현장마스터.제목`은 현장 표시명으로 유지하고 `업체명복사` 한 줄 텍스트와 `기본현장여부` 예/아니요만 추가한다. 기존 `계산서 업체 연결`은 유지한다.
- 새 업체를 입력하면 업체명과 같은 제목의 기본 현장 행을 최초 저장 시 자동 생성한다. 이 행은 `업체명복사 = 업체명`, `기본현장여부 = 예`이다.
- 사용자가 다른 현장명을 입력하면 같은 업체 아래 제목이 일치하는 행을 재사용하고 없을 때만 `기본현장여부 = 아니요`인 새 현장을 만든다.
- 같은 업체를 다시 선택하면 `업체명복사`가 같은 현장들을 드롭다운에 표시해 선택하거나 새 현장을 추가한다.
- 사용자가 현장마스터를 사전에 직접 채울 필요가 없으며, 현재 단계에서는 별도 ID 복사 열과 인덱스를 만들지 않는다. 실제 목록 규모나 위임·성능 문제가 확인될 때만 인덱스를 검토한다.
- 자동 생성은 업체명·현장명 일치 행을 상위 2건까지 조회해 0건일 때만 허용하고 2건 이상이면 중복 오류로 차단한다.
- 2026-09-04 기존 레거시 행 144건의 `업체명복사` 공란을 각 행 제목으로 채우고 `기본현장여부 = 예`로 1회 정규화했다. 이후 업체 목록은 기본 행만, 현장 목록은 선택 업체와 `업체명복사`가 같은 행만 조회하며 공란 레거시 예외 분기는 운영 수식에서 제거한다.
