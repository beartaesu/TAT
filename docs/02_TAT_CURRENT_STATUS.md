# 02 TAT CURRENT STATUS — 현재 구현 및 검증 상태

최종 갱신: 2026-08-05

## 1. 현재 도달 상태

접수 입력·항목 선택·시료별 배정·검토·저장, 접수현황 조회, 접수상세 진입, 접수상태 변경, 미접수↔측정인 구분변경의 주요 기능이 구현되어 있다. 현재 최우선 차단점은 Flow 연결 새로고침 후 `TAT_결과파일생성_App.Run()`이 15개 인수를 요구하지만 최종저장 수식이 10개만 전달하는 오류다.

## 2. 2026-08-05 확인 및 변경

- `btn구분변경실행.OnSelect`를 결과 폴더·Excel 자동 변경 Flow 호출형으로 변경했다.
- 존재하지 않는 `var상세접수.현장명` 참조는 기존 `결과폴더명`에서 이전 접수번호를 제거해 현장명을 전달하도록 수정했고 문법 오류가 사라졌다.
- Flow 첫 번째 입력은 `Round(Value(var상세접수.ID), 0)`, 나머지 입력은 `Text(...)`로 형식을 명시했다.
- 앱 재시작 후 수식 오류가 사라졌고 새 접수번호로 테스트했다.
- 신규 최종저장 테스트에서는 접수헤더와 분석항목은 저장됐으나 결과 폴더·Excel은 생성되지 않았고 Flow 실행 기록도 없었다.
- Power Apps의 Flow 연결을 새로고침하자 `15개의 인수가 필요한데 10개를 받았습니다` 오류가 표시됐다.
- 따라서 자동화가 호출되지 않은 직접 원인은 현재 최종저장 수식의 인수 부족으로 확정했다.
- Power Apps (V2) 트리거 캡처로 입력값 15개의 이름·형식·순서를 확정했다.
- 첨부된 실제 최종저장 OnSelect 전체 수식에서 Flow 호출부 4곳을 확인했다.
- 완료 건 수정 1곳과 신규 저장 분기 3곳을 모두 최신 15개 인수로 보정했다.
- 숫자 입력인 접수헤더ID는 `Round(Value(...), 0)`, 시료수는 기존 숫자식, 변경이력ID는 `0`으로 전달한다.
- 텍스트 입력은 `Text(...)` 또는 빈 문자열로 형식을 고정했다.
- 전체 교체본은 `formulas/scr검토저장_btn최종저장_OnSelect.powerfx`에 저장했다.

## 5. 알려진 오류·주의사항

### 2026-08-05 Flow 15개 인수 불일치

- Power Apps에서 `TAT_결과파일생성_App` 연결 새로고침 후 발생
- 오류: 15개 인수가 필요하지만 기존 호출부는 10개만 전달
- 신규 접수 최종저장 Flow 실행 기록 없음
- 현재 최종저장 수식에 Flow 호출부가 여러 곳이면 모든 호출을 동일한 15개 시그니처로 맞춰야 함
- 정확한 입력 순서 확인 전 임의 값 추가 금지

### 결과파일 생성 Flow 장시간 대기

`경로를 사용하여 파일 메타데이터 가져오기` 단계 입력에서 다음이 확인됨.

```json
{
  "host": {
    "connectionReferenceName": "shared_sharepointonline",
    "operationId": "GetFileMetadataByPath"
  },
  "parameters": {
    "dataset": "https://erfxxam.sharepoint.com/sites/O365_msteams_5b3dce",
    "path": null
  }
}
```

실패 표시 없이 6분 이상 대기했다. 원인은 메타데이터 단계에 전달되는 파일 경로가 `null`인 것으로 판단된다. Flow가 멈춘 뒤 재시작해도 정상화되지 않았으며 후속 진단이 필요하다.

### Flow 매개변수 기록 충돌

대화 기록에 서로 다른 `.Run(...)` 시그니처가 존재한다.

- 최근 작업 기록 A: `number, text, text_1, text_2, text_3`
- 이전 시작문 기록 B: `number, text, text_1, text_2, text_3, number_1, text_4, text_5`

다음 대화에서는 Power Apps 데이터 패널의 실제 Flow 연결과 현재 `Run` 호출 도움말을 먼저 캡처하여 확정한다.

### 기타 주의

- `txt시료명`의 길이 문제처럼 보였던 현상은 공백 제거 후 해결됨
- Office Script 이름을 영문으로 바꾸는 작업은 연결 문제 우려가 있어 임의 변경하지 않음
- 화면의 노란 경고는 기능 검증 후 한꺼번에 점검
- 트리 정리는 기능이 모두 검증된 뒤 수행
