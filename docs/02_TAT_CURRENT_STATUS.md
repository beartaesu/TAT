## 2. 2026-08-05 확인 및 변경

- `btn구분변경실행.OnSelect`를 결과 폴더·Excel 자동 변경 Flow 호출형으로 변경했다.
- 존재하지 않는 `var상세접수.현장명` 참조는 기존 `결과폴더명`에서 이전 접수번호를 제거해 현장명을 전달하도록 수정했고 문법 오류가 사라졌다.
- Flow 첫 번째 입력은 `Round(Value(var상세접수.ID), 0)`, 나머지 입력은 `Text(...)`로 형식을 명시했다.
- 앱 재시작 후 수식 오류가 사라졌고 새 접수번호로 테스트했다.
- 신규 최종저장 테스트에서는 접수헤더와 분석항목은 저장됐으나 결과 폴더·Excel은 생성되지 않았고 Flow 실행 기록도 없었다.
- Power Apps의 Flow 연결을 새로고침하자 `15개의 인수가 필요한데 10개를 받았습니다` 오류가 표시됐다.
- 따라서 자동화가 호출되지 않은 직접 원인은 현재 최종저장 수식의 인수 부족으로 확정했다.
- Power Apps (V2) 트리거의 입력값 15개 이름·형식·순서를 확인하고 최종저장 수식의 Flow 호출부 4곳을 모두 최신 인수 구조로 수정했다.
- 수정 후 `15개의 인수가 필요한데 10개를 받았습니다` 오류와 빨간 문법 오류가 사라진 것을 확인했다.
- 새 테스트 접수의 최종저장을 실행했고 결과 폴더·Excel 생성과 SharePoint 접수헤더 연결이 정상 완료됐다.
- 신규 저장의 15개 인수 적용 및 결과파일 생성 검증은 완료됐다.

### Flow 매개변수 기록 충돌

대화 기록에 서로 다른 `.Run(...)` 시그니처가 존재한다.

- 최근 작업 기록 A: `number, text, text_1, text_2, text_3`
- 이전 시작문 기록 B: `number, text, text_1, text_2, text_3, number_1, text_4, text_5`

다음 대화에서는 Power Apps 데이터 패널의 실제 Flow 연결과 현재 `Run` 호출 도움말을 먼저 캡처하여 확정한다.
