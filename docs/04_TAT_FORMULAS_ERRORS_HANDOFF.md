## 문서 역할과 갱신 기준

- 역할: 다음 세션에서 그대로 실행·검증할 수 있는 수식, Flow 표현식, 오류, 인계 자료

```powerfx
With(
    {
        var선택정산상태: dd정산상태변경.Selected.Value,
        var기존정산상태: Coalesce(var상세접수.정산상태.Value, "정산대기"),
        var기존배정상태: Coalesce(var상세접수.세금계산서배정상태.Value, "미배정")

    If(
        IsBlank(var선택정산상태),
        Notify("변경할 정산상태를 선택해 주세요.", NotificationType.Warning),
        IfError(
            Set(
                var상세접수,
                Patch(
                    접수헤더,
                    LookUp(접수헤더, ID = var상세접수.ID),
                    {
                        정산상태: {Value: var선택정산상태},
                        세금계산서배정상태: {
                            Value: If(
                                var선택정산상태 = "정산제외",
                                "정산제외",
                                var기존정산상태 = "정산제외",
                                "미배정",
                                var기존배정상태
                            )
                        }
                    }
                )
            );
            Refresh(접수헤더);
            Set(var정산상태변경패널, false);
            Notify(
                "정산상태를 '" & var선택정산상태 & "'(으)로 변경했습니다.",
                NotificationType.Success
            ),
            Notify(
                "정산상태 변경 중 오류가 발생했습니다: " & FirstError.Message,
                NotificationType.Error
            )
        )
    )
)
```

  - `공급가액`은 `수량 × 단가` 검산에 사용
- 금액 후보:
  - `공급가액합계`: 접수별 행의 `공급가액` 합계 또는 원천 `총금액`; 의미 확인 후 하나를 정본으로 확정
  - `배정기준공급가액누계`, `할인금액누계`, `발행공급가액누계`: 이관 시 `0`
  - `세금계산서미배정기준금액`: 확정된 `공급가액합계`
  - `부가세`, `항목별 총액`: 이관 금액 검산용이며 현재 대상 목록에 직접 저장하지 않음
- 안전 규칙: 동일 `접수번호` 중복 생성 금지, 마스터 불일치 Lookup 임의 생성 금지, 시험 이관 성공 전 전체 이관 금지, 기존 결과 폴더·Excel 생성 Flow 호출 금지.
- 확인 필요: `총금액`의 의미·반복 방식, 원천 데이터의 업무 상태, 시료명 분리 및 시료-분석항목 매핑 가능 여부.
- 사용자 확인 결과:
  - `총금액`은 동일 접수번호의 첫 행에만 표기되는 부가세 제외 공급가액 전체 합계이다.
  - 올해 완료 건과 진행 건이 모두 포함돼 있다.
- 확정 금액 처리:
  1. 접수번호별 첫 비어 있지 않은 `총금액`을 읽는다.
  2. 같은 접수번호의 모든 `공급가액`을 합산한다.
  3. 두 값이 같을 때만 `공급가액합계`와 `세금계산서미배정기준금액`으로 저장한다.
  4. 다르면 해당 접수의 헤더·상세를 모두 이관하지 않고 검증 오류로 분리한다.
- 상태 처리 보류: 현재 헤더만으로 완료·진행을 판정할 수 없다. 실제 Excel의 표시·규칙·별도 시트 등 구분 근거를 확인하거나 이관용 상태 열을 추가해야 한다.
- 사용자 확인: 완료·진행 및 결과 발송 여부는 별도 Excel의 수동 표기로 관리해 왔다. 자동 판정하지 않고 이관용 복사본에 아래 열을 추가한다.

  - `결과발송여부이관`: `예 / 아니요`
- 일관성 검사: 같은 접수번호의 `결과발송여부이관`은 모든 행에서 같아야 한다. 분석상태는 분석항목 행별로 다를 수 있다.

#### 2026-09-01 읽기 전용 시험 조회 결과 — 조회 검증 완료·원천 확인 필요

- 추출 행 수: 48
- 접수번호: 서로 다른 값 1개, 공란 0행
- `총금액`: 비어 있지 않은 값 1행
- `공급가액`: 숫자 48행, 합계가 첫 `총금액`과 일치

판정:

- `시험접수행필터`의 접수번호 필터와 금액 합계 검산은 성공했다.
- 반복 분석항목 행을 중복으로 삭제하거나 분석항목명만으로 합치면 시료 문맥·금액·수량이 달라질 수 있으므로 금지한다.
- 기존의 `원본 한 행 = 접수번호 × 분석항목` 판단은 폐기한다. 원천 상세 행을 각각 보존하면서 시료별 분석항목 배정을 복원한다.
- 확정 승계 규칙: 같은 접수번호 안에서는 공란 행이 다음 시료명 전까지 직전 시료명을 이어받고, 접수번호가 바뀌면 시료 문맥을 초기화한다. 새 접수의 첫 유효 시료명 전 공란에는 이전 접수 시료명을 사용하지 않는다.
- 추가 검산 결과: 시험 접수의 첫 행에는 시료명이 있으나 원천 `시료수 = 2`, 비어 있지 않은 서로 다른 시료명 묶음은 3개로 불일치한다. 사용자가 시료명을 잘못 입력했을 가능성이 있다고 확인했으므로 회사 Excel에서 어느 값이 잘못됐는지 확인·수정한다.
