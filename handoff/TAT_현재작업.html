9월 9일 이관 시작 번호 읽기 전용 확인

업체등록 화면과 실제 신규 저장 검증은 완료됐다. 다음은 이관을 실행하기 전에 번호 경계만 확인하는 단계다.

이번 단계에서는 저장·수정하지 않는다. 이관 Flow를 실행하지 않고, SharePoint 행과 접수번호관리 값을 변경하지 않는다.

1. 원천 Excel 확인

  1. tblTATMigration에서 9월 9일 이관 대상 범위를 필터링한다.
  2. 미접수 번호 형식과 측정인 번호 형식을 각각 분리한다.
  3. 각 구분에서 이관 대상의 가장 이른 접수번호를 확인한다.
  4. 동일 접수번호가 여러 분석행으로 반복되는 것은 정상이며, 접수번호 자체의 고유 목록으로 판단한다.

2. SharePoint 확인

  1. 접수번호관리에서 미접수와 측정인 각각의 현재 마지막 번호를 확인한다.
  2. 접수헤더에서 원천의 첫 대상 접수번호가 이미 존재하는지도 검색한다.
  3. 목록은 읽기만 하고 값을 변경하지 않는다.

3. 판정

  • 원천 첫 번호가 번호관리 마지막 번호 다음 순번이고 접수헤더에 없으면: 연속·신규
  • 원천 첫 번호가 번호관리 마지막 번호 이하이면: 중복 또는 번호관리 불일치
  • 번호 사이가 비어 있으면: 누락 구간 있음
  • 두 번호 체계는 서로 섞지 않고 미접수와 측정인을 각각 판정한다.

결과 회신

  • 미접수: 연속·신규 / 중복·불일치 / 누락 구간
  • 측정인: 연속·신규 / 중복·불일치 / 누락 구간
  • 두 첫 대상 번호의 접수헤더 기존 행: 둘 다 없음 / 있음
  • 데이터 또는 Flow 실행: 안 함

실제 업체명·시료명·담당자와 원천 행 내용은 이 전달 파일이나 회신에 적지 않는다.
