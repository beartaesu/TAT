현재 작업: 시험 접수 1건의 첫 SharePoint 쓰기 실행
실행 횟수: 동일 시험 접수번호로 정확히 1회

직전 작업 완료

상세 건수 작성·검증 조건을 시험상세행반복 바깥으로 교정했습니다.
False 분기를 시험이관실패요약 작성으로 변경했고 Flow 저장에 성공했습니다.

1. 첫 쓰기 실행

  1. Power Automate → TAT_이관_시험조회를 엽니다.
  2. 기존 읽기 검증에서 계속 사용한 동일 시험 접수번호를 입력합니다.
  3. Flow를 한 번만 실행합니다.
  4. 실행이 끝날 때까지 같은 버튼을 다시 누르지 않습니다.

2. 실행 기록 확인

  • 시험이관가능확인: 입력·출력 true
  • 시험이관가능조건: True 분기
  • 시험접수헤더생성: 성공, 출력에 양의 정수 ID 존재
  • 시험상세행반복: 25회 모두 성공
  • 시험생성상세건수: 입력·출력 25
  • 시험생성건수검증조건: True 분기
  • 시험이관완료요약: 접수번호·헤더 ID·상세생성 25건 표시
  • Flow 전체: 성공

3. SharePoint 직접 확인

  • 접수헤더: 해당 시험 접수번호가 정확히 1건 생성됐는지
  • 접수항목상세: 생성된 헤더에 연결된 행이 정확히 25건인지
  • 상세의 접수헤더연결과 접수헤더ID복사가 같은 새 헤더 ID인지
  • 분석항목 Lookup, 배정시료명, 수량, 단가, 분석상태가 원천과 맞는지
  • 현재 8월 자료의 분석완료일이 공란인지
  • 접수시료항목매핑은 생성되지 않았는지

알려줄 결과

  • Flow 성공 또는 실패
  • 헤더 생성 ID 존재 여부만 알려주고 실제 숫자는 적지 않기
  • 상세 생성 건수
  • 검증 조건 True/False
  • SharePoint 헤더 1건·상세 25건 여부
  • 핵심 필드 불일치 또는 공란 오류 여부
실패하거나 일부만 생성되면 같은 시험 접수번호로 재실행하지 마세요.
실패 시 정확한 실패 작업 이름과 상세 생성 성공 건수만 알려주세요. 헤더 ID 실제 숫자는 대화에 적지 않아도 됩니다.
